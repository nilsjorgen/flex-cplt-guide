1. What cplt is and how it works

cplt is a wrapper that starts your AI agent (here: GitHub Copilot CLI) inside a kernel-enforced sandbox. The agent can read, write and run things in your project, but it cannot read your secrets, push to main, merge PRs or send data wherever it likes. Every restriction also applies to every process the agent starts (Gradle, the JVM, git, curl …). At Nav, sandboxing is required for AI agent work on Nav equipment; cplt is the recommended way to do it.

It has three layers:

① Kernel sandbox

On macOS cplt generates an Apple Seatbelt profile and runs the agent under sandbox-exec. This controls file access, what may be executed, and which ports may be used. It cannot be talked around by a prompt.

② Network proxy

A local CONNECT proxy filters and logs HTTPS traffic. By default it lets everything through except a built-in list of known exfiltration hosts and hosts that resolve to private IPs. Only port 443 is open.

③ Command guards

Wrappers around git and gh. The git guard blocks pushes to the default branch and force pushes. The gh guard blocks gh pr merge, repo deletion, etc., and keeps gh scoped to the current repo.

What is blocked by default (macOS)

ResourceDefault
Project directory✅ read / write / execute
~/.gradle, ~/.m2, mise, SDKMAN, jenv (caches, toolchains)✅ allowed (but see token files below)
~/.gitconfig, ~/.config/git/config|ignore|attributes✅ read-only — but not files they include
~/.gradle/gradle.properties, ~/.m2/settings.xml, ~/.npmrc🔒 blocked (contain registry tokens)
.env*, .pem, .key inside the project🔒 blocked (read and write)
~/.ssh, ~/.gnupg, ~/.aws, ~/.kube, ~/.docker, ~/.nais …🔒 blocked
Writing .git/config, .git/hooks🔒 blocked
Executing from /tmp, /var/folders, ~/Library/Caches🔒 blocked (cplt gives the session its own scratch TMPDIR)
Outbound connections to localhost🔒 blocked
Outbound network, port 443✅ allowed via proxy (other ports blocked)
Hosts resolving to private IPs (e.g. *.intern.nav.no)🔒 blocked by proxy
Docker socket, SSH agent, clipboard🔒 blocked
Environment variablesOnly a safe allowlist passes; anything ending in _TOKEN, _SECRET, _KEY, _PASSWORD … is stripped. GH_TOKEN/GITHUB_TOKEN pass to Copilot if set.

Where configuration lives

  • Personal / machine config: ~/.config/cplt/config.toml. Written by cplt config set … (or the interactive cplt settings). The agent cannot read or edit it.
  • Per-repo team policy: .cplt.toml in the repo root, committed to git. cplt reads it from git HEAD, not your working tree, so the agent can't loosen its own sandbox mid-session.
    • [deny] only tightens; applied automatically.
    • [propose] loosens; does nothing until each developer runs cplt trust accept. Any change to the block invalidates the approval.
  • CLI flags (e.g. --allow-localhost 5432) apply for one session only.

Precedence: CLI flags → personal config → defaults. The repo file is a separate layer that can add approved permissions or deny more, but never switch off something you set. Config changes apply from the next session.

Keys marked --forceSome settings are flagged dangerous (they expose tokens, allow exec from temp, give Docker access …). cplt refuses to set them without --force, and most of them can't be put in .cplt.toml.

2. Install

brew install navikt/tap/cplt gh           # cplt + GitHub CLI
curl -fsSL https://gh.io/copilot-install | bash   # Copilot CLI → ~/.local/bin (add to PATH)

Alternatively via mise — pin the version, because cplt's version strings aren't semver and mise latest can pick an older release:

mise use -g 'github:navikt/cplt@<version>'

Upgrading (do this first when something looks off — many old errors are already fixed):

brew update && brew upgrade navikt/tap/cplt
copilot update
which -a cplt        # make sure there isn't an old copy shadowing the new one

3. Setup: Copilot CLI + Gradle + Spring Boot

3.1 One-time machine setup

Run all of this in a normal terminal, outside cplt.

1. Log in to GitHub with gh (Copilot and git push both use this login). The sub-shell clears stale token variables so the keychain login is used:

(unset GH_TOKEN GITHUB_TOKEN COPILOT_GITHUB_TOKEN GH_HOST GH_REPO; gh auth login --hostname github.com --web)
(unset GH_TOKEN GITHUB_TOKEN COPILOT_GITHUB_TOKEN GH_HOST GH_REPO; gh auth status --hostname github.com)

gh auth status should show the right account and (keyring). Never use /login inside a sandboxed Copilot session — cplt closes the Keychain, so the login can't be stored.

2. Use HTTPS for GitHub, not SSH (~/.ssh is blocked in the sandbox):

git config --global url."https://github.com/".insteadOf "git@github.com:"
gh auth setup-git

3. Make copilot always run sandboxed — this is what makes cplt "permanent":

cplt --shell-install     # adds an alias to ~/.zshrc so 'copilot' = 'cplt --agent copilot'
source ~/.zshrc
cplt doctor --agent copilot

The alias only affects interactive shells. If you also want scripts, zsh -c and IDE-launched agents to hit the sandbox, opt in to PATH shims with cplt --shell-install --shims (undo with cplt --shell-uninstall). Note: mise activate placed after the shim block in your rc files can reorder PATH; cplt doctor warns about that.

4. Install toolchains outside cplt. The sandbox deliberately can't write to mise's install directory, so a missing version fails inside cplt. In each repo, once:

mise install          # install the versions in mise.toml / .tool-versions
./gradlew build       # first run outside cplt: downloads the wrapper distribution and any toolchain JDK
JDK locationJDKs in ~/Library/Java/JavaVirtualMachines (where IntelliJ downloads them) are not supported yet. Point JAVA_HOME at a mise, SDKMAN or /Library/Java/JavaVirtualMachines JDK instead.

3.2 Personal baseline config

What belongs hereAnything about your machine: paths in your home directory (allow.read/allow.write), machine tools like the IntelliJ MCP port, env vars, the clipboard, logging, and every --force setting (token files, temp exec, Docker) — these can't go in .cplt.toml anyway. Each row in the cheat sheet says where it belongs.

Settings that are about your machine belong in your personal config. A sensible minimum for a Gradle/Spring Boot developer:

# Gradle daemon, Kotlin daemon and Spring Boot dev servers talk over random localhost ports
cplt config set sandbox.allow_localhost_any true

# MockK / Mockito inline / ByteBuddy attach to the JVM during tests
cplt config set sandbox.allow_jvm_attach true

# IntelliJ MCP server (see 3.4) – explicit, in case you ever turn allow_localhost_any off
cplt config set allow.localhost 64342

# Keep a quiet, always-on log of every network connection (grep it when something fails)
cplt config set proxy.log_file ~/.cache/cplt/proxy.log

If your ~/.gitconfig uses include/includeIf to pull in other files, also grant read access to each included file (not the folder) — see troubleshooting:

cplt config set allow.read ~/.config/git/work

Check the result with cplt config show; remove a value with --unset, e.g. cplt config set allow.read ~/.npmrc --unset.

What allow_localhost_any costsThe agent can then reach every service listening on localhost, including a local database. If you'd rather not, put it in each repo's .cplt.toml instead (next section) so it only applies there.

3.3 Per-repo config (.cplt.toml)

What belongs hereAnything the project needs, so every teammate gets the same sandbox: allow_localhost_any and allow_jvm_attach for Gradle, fixed ports for services from docker compose, internal hosts the build resolves (proxy.allow_private_domains), extra ports. Never paths in someone's home directory, and never Docker. If you put the Gradle settings in your personal config (3.2), they're still worth committing here for the rest of the team. See the cheat sheet.

For settings the whole team needs, commit a .cplt.toml. Let cplt suggest one:

cplt init              # preview only, writes nothing

Review the [propose] block. Commented-out lines refer to files in your home directory and belong in your personal config, not the repo. Remove allow_docker if it suggests it (see Docker). For a Spring Boot + Gradle app with Postgres from docker compose, you typically end up with:

# .cplt.toml
[propose]
allow_localhost_any = true   # Gradle/Kotlin daemons use random ports
allow_jvm_attach   = true    # MockK / Mockito inline

[propose.allow]
localhost = [5432]           # Postgres from docker compose (redundant with allow_localhost_any, but documents intent)

# Internal Nav hosts the build needs? Add them with:
#   cplt config set --repo proxy.allow_private_domains repo.adeo.no

Write, commit and approve:

cplt init --write
git add .cplt.toml && git commit -m "chore: add cplt sandbox config"
cplt trust accept --all     # each developer runs this once on their machine
cplt trust show             # what's approved, what's pending

Adding to an existing file later: cplt config set --repo allow.localhost 5432 (writes the proposal) or cplt init --write --merge (adds new findings, removes nothing). Commit, then cplt trust accept again.

Gradle things cplt already handles for you Gradle 8.8+ tries to start its own nested macOS sandbox, which can't run inside cplt — cplt sets GRADLE_MACOS_SANDBOX=off automatically. It also injects proxy settings into JAVA_TOOL_OPTIONS, so Gradle/Maven dependency downloads go through the cplt proxy (and show up in its log).

Other agents and sandbox commands

From the cplt README — handy for testing whether a build works in the sandbox before you hand it to the agent:

cplt --agent opencode                       # OpenCode (Copilot subscription)
cplt --agent opencode --pass-env ANTHROPIC_API_KEY  # third-party provider
cplt --agent shell                          # interactive sandboxed shell (no AI)
cplt exec -- npm install                    # sandbox any command directly
cplt exec -c "npm install && npm test"      # compound commands in sandbox
alias npm="cplt exec -- npm"               # sandboxed npm for every invocation

The Gradle equivalents: cplt exec -- ./gradlew build and cplt exec -c "./gradlew clean test". Combine with cplt config set proxy.log_level blocked to see exactly what the build is denied.

3.4 IntelliJ MCP server (SSE)

The IntelliJ MCP server is built into IntelliJ IDEA 2025.2+. It listens on localhost (first IDE on port 64342, a second IDE on 64343, …), which the sandbox blocks by default.

  1. In IntelliJ: Settings → Tools → MCP Server → Enable MCP Server. Either click Auto-Configure for GitHub Copilot CLI, or use Copy SSE Config and paste it into ~/.copilot/mcp-config.json. It ends up looking roughly like: 
    {
  "mcpServers": {
    "intellij": {
      "type": "sse",
      "url": "http://127.0.0.1:64342/sse",
      "tools": ["*"]
    }
  }
}
  2. Open the port in cplt (already in the baseline above): 
    cplt config set allow.localhost 64342
    Use 64343 too if you often have two IntelliJ windows/IDEs open.
  3. Start a new session and check the server is listed with /mcp in Copilot.
The IntelliJ MCP server runs outside the sandboxAnything the agent asks IntelliJ to do happens with your full permissions — the cplt docs say the same about any socket you open to a process outside the sandbox. In particular, IntelliJ's execute_terminal_command tool runs commands unsandboxed. Keep IntelliJ's "brave mode" off so it asks for confirmation, and actually read those confirmations. (This is my note, not from the Nav docs.)

3.5 Daily use

cd ~/src/my-app
copilot                          # = cplt --agent copilot (via the alias)
copilot -p "fix the failing tests"
cplt --continue                  # resume the most recent session in this directory
cplt --resume                    # pick a session interactively
cplt exec -- ./gradlew build     # run any single command in the sandbox (handy for debugging)
cplt --agent shell               # an interactive sandboxed shell, no AI

At startup cplt prints a summary of the active rules and asks you to confirm the first time (or when the profile changed). At the end it prints an audit of what the session changed. You can see the full generated profile with cplt --print-profile.

The line Sandboxing is disabled for this session because this host does not support it from Copilot is expected: Copilot's own sandbox can't nest inside cplt, so cplt switches it off. cplt is still the sandbox.

Copying text from the agent's output

Copying from the agent can be awkward. Two things help:

  1. Hold Fn while you select the text, then press ⌘+C. This almost always works.
  2. Deal with copy-on-select. Copilot CLI has a built-in copy-on-select, which doesn't work well because cplt blocks clipboard access by default. Either:
    • turn off copy-on-select in /settings inside the agent, or
    • let the agent use the clipboard: 
      cplt config set --global sandbox.deny_clipboard false   # permanently
cplt --allow-clipboard                                 # this session only
      The trade-off: the agent can then also read whatever you last copied (a password, a token …).

4. Git & GitHub in the sandbox

The agent can commit, branch, fetch, rebase and push its own branches, and open PRs. It cannot push to main/master/the default branch, force push, or merge PRs — you merge.

git push origin HEAD:my-branch
gh pr create --head my-branch

The -u quirk on macOS: .git/config is read-only in the sandbox, so cplt strips -u from git push -u (you'll see cplt: pushing without -u) and sets the upstream itself when the session ends. If it can't, it prints a git branch -u origin/my-branch my-branch command for you to run outside cplt. Without a terminal, gh pr create won't push for you — push first, then pass --head.

Run these yourself, outside cplt (they write to protected git files):

  • git config (incl. --global), git remote add, git remote set-url
  • git branch -u when cplt couldn't set the upstream
  • git clone, git init, git submodule add, git worktree add/remove
  • creating or changing git hooks
  • ktlint / detekt Gradle tasks (e.g. ./gradlew ktlintFormat) — their worker processes don't pick up cplt's settings

Commits made by the agent are unsigned (~/.gnupg and ~/.ssh are closed).

5. Private packages (GitHub Packages)

Many navikt libraries live in GitHub Packages, which needs a token — usually in ~/.gradle/gradle.properties. cplt blocks that file on macOS, and Gradle stops when the file exists but can't be read (Error when loading properties file …). Options, safest first:

A. Use Nav's mirror (no token needed). An open mirror of the public packages:

// build.gradle.kts
repositories {
    mavenCentral()
    maven("https://github-package-registry-mirror.gc.nav.no/cached/maven-release")
}

Then remove the token from gradle.properties (or remove the file if it only held the token).

B. Let the agent read the one file. The agent can then read every token in it — use a token with only read:packages:

cplt config set allow.read ~/.gradle/gradle.properties

(cplt config set sandbox.allow_build_credentials true --force opens gradle.properties, ~/.m2/settings.xml and ~/.npmrc at once. Personal config only.)

C. Token from the environment. If the build reads GITHUB_TOKEN, Copilot receives it as set in your shell (other agents and cplt exec need --pass-env GITHUB_TOKEN).

Received status code 401 from server: Unauthorized means the request got through the network — the token is what's missing.

6. Docker & Testcontainers

Docker is blocked: anyone who can talk to the Docker daemon can start a container that mounts your whole disk, which defeats the sandbox. So Testcontainers fails inside cplt. Options, safest first:

  1. Run container-based tests outside cplt. Let the agent run the rest (e.g. exclude integration tests via a Gradle task/tag).
  2. Start services yourself and open their ports — works for docker compose, not for Testcontainers (which starts its own containers): 
    docker compose up -d                          # outside cplt
cplt config set --repo allow.localhost 5432   # or personal config without --repo
  3. Give the agent Docker, ideally for one session and only in a repo you trust. The agent can then do anything Docker can, and read ~/.docker (registry logins). Testcontainers also needs random localhost ports: 
    cplt --allow-docker --allow-localhost-any                   # one session
cplt config set sandbox.allow_docker true --force           # permanently
    With colima, keep TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock set as usual; cplt passes DOCKER_HOST and TESTCONTAINERS_* through.

7. Allowlist / strict mode

By default the network is open except for a blocklist. You can flip it to fail-closed, where only listed hosts are reachable:

  • proxy.default_allowlist = true — the agent's own hosts (GitHub/Copilot) + common package registries (Maven Central, Gradle plugins, npm, PyPI, …).
  • proxy.allowed_domains = "~/.config/cplt/allowed-domains.txt" — your own list file, one host per line, re-read every 5 s. Must live outside the project.
  • --preset strict / sandbox.preset = "strict" — turns on the default allowlist and forces all traffic through the proxy, blocks every push, and ignores allow_localhost_any (so the Gradle daemon breaks unless you skip forced proxy).

Add hosts to an active list with allow.domains (it extends a list; it does not turn one on). Subdomains are included.

cplt config set proxy.default_allowlist true

# Gradle wrapper distribution (not in the default list)
cplt config set allow.domains services.gradle.org
cplt config set allow.domains release-assets.githubusercontent.com   # github.com is already allowed for Copilot

# Toolchain download via foojay
cplt config set allow.domains api.foojay.io

# Nav's GitHub Packages mirror
cplt config set allow.domains github-package-registry-mirror.gc.nav.no

cplt config hosts --agent copilot     # see which hosts are always allowed

Find the hosts your build needs: run it once without enforcing an allowlist and let cplt record what it contacted:

cplt --observe-domains exec -- ./gradlew build

Blocked-by-allowlist calls show up as BLOCKED-ALLOWLIST in the proxy log; cplt check net <host> tells you why and how to fix it. Escape hatch for one run: --allow-all-domains.

8. Troubleshooting blocked resources

First: ask cplt

cplt check                                  # is the sandbox working at all?
cplt check net example.com                  # ALLOWED / BLOCKED, with Reason: and often Fix:
cplt check path ~/.config/git/work          # may the agent read/write this path?
cplt check exec /bin/ps                     # may it execute this?
cplt config set proxy.log_level blocked     # print blocked network calls live during the session
cplt config explain sandbox.allow_env_files # what does a key do?
cplt doctor --agent copilot                 # overall health check (paste this when reporting a bug)
cplt --show-denials -- -p "…"               # stream macOS sandbox denials in real time

Rule of thumb: network problems appear in the proxy log; file / localhost / exec problems don't — use cplt check path / --show-denials for those. Remember changes apply from the next session. Use a flag (e.g. --allow-read PATH) to try something for one session before making it permanent.

Network

The agent can't reach a website / API

Check first: cplt check net api.example.com. Then, depending on the reason:

  • BLOCKED-ALLOWLIST — you have an allowlist on. Add the host: cplt config set allow.domains api.example.com (or append it to the file in proxy.allowed_domains; cplt config get proxy.allowed_domains shows which file).
  • Built-in blocklist (pastebin, webhook.site, tunnels…) — blocked on purpose.
  • Non-443 port (e.g. :8443) — cplt config set allow.ports 8443.
  • Private IP — see next entry.

Note: the proxy is not forced by default, so a tool that ignores HTTPS_PROXY may connect directly on 443 and bypass host rules.

Failed to CONNECT: 403 Forbidden — Private target blocked by cplt (internal Nav hosts)

The host resolves to a private IP (e.g. repo.adeo.no, *.intern.nav.no). The proxy log shows BLOCKED-PRIVATE. This also hits Gradle/Maven repos, since the JVM goes through the proxy. Allow by DNS name (covers subdomains):

cplt config set proxy.allow_private_domains repo.adeo.no
cplt config set proxy.allow_private_domains intern.nav.no
# one session only:
cplt --allow-private-domain repo.adeo.no
# for the whole team: --repo, commit, cplt trust accept

URLs written as a raw IP (https://10.20.30.40/…) cannot be allowed by any setting — use the hostname. If you also have an allowlist, the domain must be on it too.

Unable to download toolchain (Gradle foojay)

Looks like a network error but is usually a write block: ~/.gradle/jdks is read-only in the sandbox. Run the build once outside cplt so the JDK is already there, or use an installed JDK and disable auto-download in the project's gradle.properties:

org.gradle.java.installations.auto-download=false

With an allowlist, also add api.foojay.io and release-assets.githubusercontent.com.

Localhost

connect EPERM 127.0.0.1:… / Connection refused to a local service

Localhost is closed on macOS. Open one port for a fixed-port service, or all ports for tools that use random ports:

cplt config set allow.localhost 5432
cplt config set sandbox.allow_localhost_any true

Use allow.localhost, not allow.ports — the latter opens a port to the internet and doesn't cover localhost on macOS. Note the agent can still start your Spring Boot app and you can open it in your browser; it's only the agent connecting to it that needs this.

Could not connect to the Gradle daemon / ConnectException: Could not connect to server

The Gradle and Kotlin daemons talk over random localhost ports. --no-daemon doesn't help. Fix: cplt config set sandbox.allow_localhost_any true. If you see only Last 20 lines from daemon log file, the real error is further up.

Still failing with addresses:[/127.0.0.1]? Usually ktlint or detekt — run those tasks outside cplt.

IntelliJ MCP tools don't show up / fail to connect

Make sure the MCP server is enabled in IntelliJ, IntelliJ is running, and the port in ~/.copilot/mcp-config.json matches (64342 for the first IDE). Then cplt config set allow.localhost 64342 and start a new session. Verify with /mcp in Copilot.

Files & programs

Operation not permitted, EPERM or EACCES on some path

Run cplt check path <path>. Then grant the narrowest thing that works:

cplt config set allow.read  ~/some/file-or-dir     # read-only
cplt config set allow.write ~/some/dir             # read/write, NOT executable
cplt --allow-read ~/some/file                      # one session only

Some paths can never be opened (~/.netrc, ~/.git-credentials, ~/.config/cplt …). Common cases follow.

fatal: unable to access '~/.config/git/work': Operation not permitted (gitconfig include)

Your git config has an include/includeIf pointing to another file. The agent can read only ~/.gitconfig and ~/.config/git/{config,ignore,attributes}, and git aborts when an include can't be read. Grant the specific file (not the folder):

cplt config set allow.read ~/.config/git/work

Repeat for each included file. A symlinked (stowed) ~/.gitconfig is followed automatically.

Error when loading properties file=…/.gradle/gradle.properties (Operation not permitted)

The file is blocked because it usually contains tokens. See Private packages: move to Nav's mirror and remove the token, or cplt config set allow.read ~/.gradle/gradle.properties.

Could not self-attach to current VM using external process

MockK/Mockito/ByteBuddy need the JVM attach socket. cplt config set sandbox.allow_jvm_attach true (opens only /tmp/.java_pid<PID>).

Operation not permitted while the JVM is starting

Some JVM libraries load native code from the system temp dir before cplt redirects it. Only if the error is at JVM startup:

cplt config set sandbox.allow_tmp_exec true --force
JDK under ~/Library/Java/JavaVirtualMachines doesn't work

Not supported yet. Point JAVA_HOME at a JDK installed via mise, SDKMAN, jenv or under /Library/Java/JavaVirtualMachines.

failed create_dir_all ~/.local/share/mise/installs/…: Operation not permitted

A tool version is missing and the agent may not install it (on purpose — a binary the agent downloads could escape the sandbox). Run mise install outside cplt. mise run and already-installed tools work fine.

Spring Boot / dotenv can't read .env files, or fatal: cannot hash .env.local

.env*, .pem, .key files are blocked for read and write. If the project needs them (the agent can then read all secrets in them):

cplt config set sandbox.allow_env_files true   # always
cplt --allow-env-files                         # this session

cannot hash means a secrets file is tracked in git — untrack it: git rm --cached .env.local && echo ".env.local" >> .gitignore.

execvp() of /bin/ps failed / openpty: Operation not permitted

setuid programs (ps, top, sudo) and programs creating their own terminal (script, tmux, screen) can't run in the sandbox. No setting changes this — run them outside cplt.

Operation not permitted in ~/Desktop or ~/Documents

That's macOS privacy protection (TCC), not cplt. Give your terminal Full Disk Access in System Settings → Privacy & Security, or copy the file into the project.

Git & GitHub

error: could not write config file .git/config: Operation not permitted

.git/config is read-only (it can make git run code outside the sandbox). See Git & GitHub for the -u behaviour. Run git config/git remote commands outside cplt.

BLOCKED by sandbox: 'git push' is not allowed in this environment.

Push to default branch or force push. Push to a feature branch: git push origin HEAD:my-branch. If even a new branch is blocked with the default branch of remote 'origin' could not be determined, run outside cplt: git remote set-head origin -a, then start a new session.

BLOCKED by sandbox: 'git remote' would change a remote's URL.

Changing origin (or url.*.insteadOf) is always blocked — the gh guard uses origin to decide which repo the agent may touch. Do it outside cplt. If your tests create repos with an origin, run them with cplt --no-git-guard exec -- <command>.

which is outside the startup repo (gh)

The gh guard limits the agent to the repo it was started in. To add another: cplt link navikt/other-repo.

Permission denied (publickey)

SSH keys are blocked. Switch to HTTPS, outside cplt:

git remote set-url origin https://github.com/navikt/<repo>.git
(unset GH_TOKEN GITHUB_TOKEN COPILOT_GITHUB_TOKEN GH_HOST GH_REPO; gh auth setup-git --hostname github.com)
aborted: you must first push the current branch to a remote, or use the --head flag 
git push origin HEAD:my-branch
gh pr create --head my-branch

Login & Copilot

System vault not available, or /login wants to store the token in plain text

cplt closes the Keychain when it hands Copilot your gh token, so /login inside the sandbox can't save. Choose No, cancel sign-in, exit, and log in outside cplt:

(
  unset COPILOT_GITHUB_TOKEN GH_TOKEN GITHUB_TOKEN GH_HOST GH_REPO
  gh auth login --hostname github.com &&
  gh auth status --hostname github.com
)
# then, from the repo:
(unset COPILOT_GITHUB_TOKEN GH_TOKEN GITHUB_TOKEN GH_HOST GH_REPO; cplt doctor --agent copilot; copilot)

Check that gh shows the right account and (keyring), and that this account has Copilot at github.com/settings/copilot. A stale exported GH_TOKEN wins over the keychain and breaks sign-in — cplt doctor warns about it.

Copilot hangs right after startup

If your organisation's managed Copilot policy requires Copilot's own sandbox, cplt can't turn it off and the two collide. Check with cplt doctor --agent copilot and raise it with whoever manages the policy.

Version & config

unknown config key / .cplt.toml uses a key this version of cplt does not understand / unexpected argument

Your cplt is older than the docs or the repo's config. brew upgrade navikt/tap/cplt, and check which -a cplt for a stale copy (e.g. in ~/.local/bin). Validate your own config with cplt config validate. If you have an old [audit] section in your config, delete it (use proxy.log_file instead).

Reporting a bug

Paste the output of cplt doctor (it shows home as ~ and tokens by name only) plus the failing command in an issue at navikt/cplt. Don't paste --verbose output publicly; it has full paths.

👤 Personal = ~/.config/cplt/config.toml via cplt config set … · 📁 Repo = .cplt.toml via cplt config set --repo …, commit, cplt trust accept · ⏱ Session = a CLI flag for one run.
Rule of thumb: the project needs it → repo; it's about your machine, your home directory or your secrets → personal; it's risky → session.

How to apply any of these:

  • Personal (all repos): cplt config set <key> <value>
  • Team (this repo): add --repo → proposes it in .cplt.toml; commit, then cplt trust accept
  • Remove a value: add --unset
  • One session only: use the matching flag instead:
    • --allow-localhost 5432
    • --allow-read PATH
    • --allow-port 8443
    • --allow-docker
    • --allow-env-files
    • --pass-env VAR
  • Takes effect: from the next session
